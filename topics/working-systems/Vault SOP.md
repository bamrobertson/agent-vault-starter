# Vault SOP

## Source order

Current user instruction → approved decision → active maintained SOP → section index → research/draft → historical log. Resolve conflicts explicitly rather than silently combining rules.

## Creating or updating a note

1. Read the nearest index and search for an existing note.
2. Update its maintained entry point if appropriate; create a new note for a distinct decision or project.
3. Link new notes from the nearest index. Mark drafts and superseded material accurately.
4. Record a source and date for changing facts; verify against the live source when making a current claim.
5. Keep large exports and disposable files out of the vault. Store durable evidence next to its topic when needed.

## Learning loop

Capture a feedback example with the original output, correction, observed cause and revised rule. Update the relevant instruction only when the correction is reusable and authorized. On the next matching case, check whether the rule was applied; record the result. A successful edit is not proof the next run followed it.

## Safety and continuity

Separate work and personal content. Keep secrets and private source bodies out of Git and shared status notes. For automation, record its schedule, exact target, permissions, source coverage, ledger and stop condition. Verify the saved configuration and a real scheduled run before calling it reliable.
